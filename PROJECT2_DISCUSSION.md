# Project 2 Discussion Answers

1. **Distance vector vs. link state.** This implementation stores one selected route per destination and exchanges bounded vectors only with direct neighbors. Link state stores a network-wide link map and floods link-state advertisements. DV has smaller per-node topology state and simpler local updates, but convergence can be slower and temporary loops can occur. Link state uses more control traffic and memory for global topology, then runs a shortest-path computation; its implementation is more involved.

2. **Why process a worse update from the next hop?** Suppose node A reaches D through B at cost 2. If B loses its route and advertises 16, A must withdraw its route. If A accepts only smaller costs, it keeps the stale cost 2 forever, continues sending packets to B, and never recovers correctly. The implementation processes increases and poison from the selected next hop and expires stale selected routes.

3. **Split horizon and poisoning.** If A reaches D through B, simple split horizon omits D from A's vector to B. Poison reverse includes D with cost 16 to B; A sends its finite cost to another neighbor C. After a failure, route poisoning advertises 16 to neighbors to withdraw the failed route. Poison reverse blocks the two-node A-B feedback route, but three nodes can still advertise stale paths to one another during convergence; bounded cost and packet TTL limit the damage.

4. **Path symmetry.** Forward and reverse routes need not be symmetric. Each node learns routes independently, and equal-cost ties retain each node's current next hop. Asymmetric links, different information timing, and local ties can therefore select different paths in each direction.

5. **Lost or malformed advertisements.** A lost page provides no new information; omission is not a withdrawal. Periodic staged vectors resend entries. The receiver checks the fixed packet length, count, and cost bounds before reading entries, and malformed packets are ignored. Per-destination ages expire routes whose selected information stops arriving. A full send queue causes a page retry.

6. **Flapping or non-forwarding nodes.** Repeated advertisements and withdrawals can destabilize neighbors; a node may also advertise a route without actually forwarding. One possible mitigation is a hold-down timer or route-flap dampening, which delays reuse of unstable routes. This implementation uses a bounded metric, TTL, route freshness, and a finite withdrawal interval but does not implement hold-down. Hold-down can slow legitimate recovery, and no control-plane metric alone proves that a node forwards correctly.
