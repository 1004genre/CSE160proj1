# Project 2 Design Summary

the routing table is a statically allocated array indexed by the 8-bit destination ID. each entry stores the validity, selected next hop, path cost, age since its last selected-next-hop update, and an unreachable withdrawal timer. the node's own route is always valid at cost 0. neighbor discovery keeps at most 32 entries and confirms a bidirectional link with a beacon, ack, and confirmation. In the required hop-count mode each confirmed neighbor has a direct route of cost 1; optional quality-aware mode uses its measured link cost. excess neighbors are logged and ignored.

distance-vector control packets use AM and are sent directly to one neighbor, independent of the data route. each packet reuses the fixed 28-byte `pack` format. its payload contains a count and up to nine byte pairs (destination, cost). a staged sender emits one page every 250 ms and retries a page if the SimpleSend queue is full. it sends all known finite and withdrawal entries to each neighbor; omission in one page does not change a route. Recipient-specific poison reverse advertises the active mode's infinity (16 for hop count, 255 for quality-aware) for destinations whose selected next hop is that recipient, while the self-route is always 0.

the hop metric is bounded by `INFINITY = 16`; addition is checked before incrementing. advertisements keep the current valid next hop. a selected next hop can raise or withdraw its route but worse candidates from other neighbors are ignored. each learned route ages independently and expires after 300 seconds without a refresh. neighbor loss invalidates every route using that next hop immediately after the neighbor table expires (5 missed 1-second beacons). newly unreachable entries remain advertised as 16 for 1200 seconds, then may be reclaimed; a newly learned finite route cancels withdrawal.

a 1-second age timer starts the next staged round when neighbors exist and the previous round is complete. Its initial firing is randomized to reduce synchronized startup transmissions. Learned routes expire after 300 seconds; this exceeds the maximum configured full advertisement round (32 neighbors, 256 destinations, 9 entries per page, staged every 250 ms) while reducing stale-route retention from ten minutes. There are 256 route slots, 32 neighbor slots, 9 entries per DV packet, and a 20-message send queue/pool per SimpleSend component.

ping and ping reply share the existing network header and use AM type 6 for unicast next-hop forwarding. end-to-end source, destination, protocol, and sequence remain unchanged. the source starts TTL at 15 and a relay drops TTL <= 1, otherwise decrements once. destination delivery requires positive TTL. flooding remains in its own service and is selected only for radio broadcasts; routed unicast packets never consult the flood duplicate cache and never fall back to flooding.

## Optional loss-aware metric

hop count remains the default required metric. it measures an outbound link using the existing periodic neighbor beacons: every beacon carries a sequence number, and a neighbor returns that number in its ack. a missed ack is one failed probe and a matching ack is a successful probe. this is conservative beacon/ack exchange delivery probability rather than relying on radio gain alone.

for estimated delivery score `q`, the direct-link cost is `ceil(8 * 255 / q)`. zero quality or a cost at/above infinity is treated as unreachable. thus a perfect link costs 8, a less reliable link costs more, and no link has zero cost. advertisements carry the accumulated additive cost in the existing one-byte vector entries. quality-aware routes reserve 255 for infinity and reject sums that reach it. hop-count mode retains infinity 16 and its original unit edge cost. both modes use poison reverse, selected-next-hop increases/withdrawals, neighbor expiry, route aging, and TTL. positive link costs avoid zero-cost cycles as it's bounded accumulation and poison reverse constrain transient distance-vector loops.
